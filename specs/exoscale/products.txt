# Produits Exoscale suivis par le générateur, un par ligne.
#
#   <tag-racine> [<nom-produit>] <version>
#
# Exoscale publie UN SEUL document OpenAPI pour tous ses produits
# (https://openapi-v2.exoscale.com/source.json). Un produit n'est donc pas un
# fichier, c'est une famille de tags : `instance` a pour parent `compute`,
# `vpc-subnet` a pour parent `vpc` qui a pour parent `compute`. La ligne indexe
# le tag RACINE, et `generator/source/base.py` découpe le document sur toute
# sa descendance.
#
# Le tag se vérifie dans la liste `tags` du document, pas dans l'URL du portail
# ni dans le SDK : `python -m generator products` recense chaque racine avec
# son nombre d'opérations, nomme les tags employés sans être déclarés (mesuré :
# ccm, organization, quotas) et les opérations sans aucun tag (mesuré : 2).
#
# Le nom du produit est le préfixe des modules et le nom du fichier
# d'overrides : un tag à tiret (`block-storage`) reçoit un nom en snake_case,
# parce qu'un nom de module Ansible n'accepte pas de tiret.
#
# Les quatorze racines du document sont indexées, `ccm`, `organization` et
# `quotas` compris, qui sont employées sans être déclarées : les règles de
# classification laissent zéro UNKNOWN sur chacune, mesuré par
# `mise run products`. Les deux opérations sans aucun tag
# (`get-impact-estimate`, `get-impact-report`) n'appartiennent à aucune
# famille : le recensement les nomme à chaque exécution, et elles ne sont
# portées par aucun module.
